# Callable value flow checkpoint

FB01/FB02/FB03/FB07/FB08 now include bounded function-item acquisition and value-sensitive Rust function-pointer composition. All package and gate acceptance obligations remain active. This work was developed from controlled compiler fixtures, independently of the reserved Serde holdout.

## Fundamental observations

The pinned MIR worker has a new opt-in `library-guides.mir-callables.v1` format. Set `LIBRARY_GUIDES_MIR_CALLABLES=1` together with the existing behavior and instance-budget options. The original invocation identity includes this option and schema; requesting callable capture without an instance budget fails. The `mir_callables` source lane uses `mir-callables.v1.schema.json`, generated by `callable-schema`. Earlier generic and instance wire formats remain separate.

Each projected function-item operand retains its exact block, optional statement, operand role and index, original declaration/definition and substitutions, pointer-coercion status, and captured-instance disposition. Item-to-pointer reification uses the pinned compiler's `Instance::resolve_for_fn_ptr`; only non-foreign item bodies are supported. Unsupported shims and unresolved substitutions remain explicit. No display-name or machine-address identity is used. The original compiler options bound instance attempts/depth/candidates; function-reference observations have a separate hard limit of 100,000. This enumerates function items in supported projected operands, not every closure, vtable, drop or foreign executable use.

Validation requires exactly one reference for every retained function-item operand. Duplicate/missing operands, wrong compiler units, wrong target definitions/substitutions and missing captured bodies in complete catalogs are rejected. Normalization retains a function value only from a captured compiler-qualified item. Other references remain unknown values with capture frontiers.

## Reusable interpretation and selection

MIR projection v3 preserves qualified function values through assignments, guarded paths, aggregates, field updates, returns and call arguments. The interpreter follows an indirect call only when the evaluated value identifies one exact selected body. External pointer inputs, missing bodies, unresolved joins and unsupported coercions use conservative call/effect/outcome treatment. The existing memory model supplies the field transfer; there is no API-specific rule. Function-item identity does not establish pointer-address equality, arbitrary callable equivalence, closure capture semantics or lifetime guarantees.

Call-index v3 retains the complete compiler owner/call denominator and original reference support. Helper selection follows captured references under the same depth/owner/byte budgets as calls. The new `callable_closures` family keeps reference coordinates and dispositions separate from executed call observations; old `call_closures` records retain their schema and meaning. Reference selection denotes potentially needed bodies, not proof that they execute. Exact source support, stage ownership, replay and portable closure include both kinds of selection.

Guarded transfer v2 is selected for populations containing MIR v3. Other populations retain transfer v1. The recursive fallback remains a checked conservative envelope. Dynamic-call dependency scope includes the complete selected body population, with an explicit edge-work bound before graph growth. Open target sets never become empty successful call sets.
