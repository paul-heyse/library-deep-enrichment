# Bounded concrete Rust instance checkpoint

FB02/FB03/FB07 now have opt-in acquisition and interpretation of observed concrete item instances. No package or gate is marked complete. The named requirement is const/type substitution that changes a callee's executable body; a generic definition alone cannot supply that specialized relationship.

## Acquisition and identity

The existing pinned nightly worker emits a separate `library-guides.mir-instances.v1` format when `LIBRARY_GUIDES_MIR_BEHAVIOR=1` and `LIBRARY_GUIDES_MIR_INSTANCES` are set. The latter is an integer attempt limit from 1 through 128. `LIBRARY_GUIDES_MIR_INSTANCE_DEPTH` selects depth 0 through 8, default 2. Tracked candidates have an independent fixed limit of 4,096. Ordinary generic capture and its legacy schema remain unchanged; the generated legacy schema was compared structurally to its existing asset.

Within the compiler callback, the worker resolves concrete, non-foreign item calls and requests the pinned `Instance::body()` surface, which supplies eagerly monomorphized bodies and evaluated constants. A finite ordered queue and per-instance deduplication bound body acquisition. All compiler handles are destroyed inside the callback; only owned records and counters cross that boundary. The first compiler build rejected a collector captured outside this boundary because its thread-local handles were not `Send`; the implementation now creates and consumes that collector within the callback.

Instance identity combines the observing compiler unit, definition/build identity, instance kind, compiler mangled name and complete owned argument projection. Different compiler instances colliding under that identity fail acquisition. The mangled name alone is not identity. Generic and concrete body phases remain distinct. The original invocation identity includes the selected schema, actual working directory, provider digest and instance limits. New frame headers also retain these limits, and normalization exposes them as observed context settings.

Every explicit call has a terminal capture disposition: captured, unavailable body, instance/depth/candidate budget, unresolved type/dispatch, or unsupported foreign/non-item instance. Finite transport completion does not mean every possible specialization was captured. Original generic owners remain present when concrete acquisition hits a bound. Body count limits do not bound the compiler's internal cost for one body; existing outer process supervision and output limits remain relevant.

Compilation reconciliation accepts the new format and joins the exact retained original invocation witness. Stage fingerprints, reference closure and replay include the new helpers.
