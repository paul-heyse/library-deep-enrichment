# Exact-definition instance demand checkpoint

Concrete body acquisition can now start from an explicit finite set of compiler definitions. Set `LIBRARY_GUIDES_MIR_INSTANCE_ROOTS` to a JSON array of exact `definition:...` identities from the same compilation context, alongside the existing explicit instance budgets. Up to 128 unique roots are accepted; roots are canonically sorted. An absent requested root fails the selected compiler unit instead of producing an apparently successful empty selection.

The complete generic body, call, callable-reference and drop denominator is still collected. Only the requested generic roots enqueue new instance candidates; their captured dependencies continue breadth-first under the existing attempt/depth/candidate budgets. Other uses retain `outside_requested_root_closure` unless their exact body was captured through a requested root, in which case they can reuse its final disposition. This permits useful shared-body reuse without spending additional acquisition budget on unrelated owners.

The root catalog is included in the original invocation identity and frame options. Changing it invalidates the acquisition identity. Omitting the option preserves the prior serialized options and acquisition behavior. Roots apply to one selected compiler unit; they are not symbol-name patterns or a whole-workspace discovery filter. Source/context qualification and remaining semantic obligations still apply.

An actual compiler control starts at the disposal operation, preserves every generic owner from the unrestricted capture, retains explicit nonrequested calls, captures the transitive custom-drop glue and uses fewer concrete bodies. A changed root catalog fails invocation-identity validation; an absent root fails extraction without producing a committed frame stream. Eleven lifecycle/callable/instance/call-index tests pass in 40.91 seconds (`root-demand-tests-v4.log`). After making the parsed-options constructor explicit for type checking, the three lifecycle/demand tests pass in 6.36 seconds (`root-demand-tests-v5.log`). Ruff, formatting, Pyrefly and native Clippy pass. The preceding full-suite receipt remains 454 tests at the lifecycle checkpoint; a new full suite has not been claimed for this additional feature.

This is progress on FB03/FB07/FB16. Per-owner/SCC recovery, real-population resource qualification and all broader acceptance gates remain open. The feature provides a general acquisition mechanism; it does not certify any particular library binding or reduce the frozen public-candidate denominator.
