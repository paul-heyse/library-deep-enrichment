# 0001. Remove the static-document evidence lane

Date: 2026-09-13
Status: accepted

## Context

Inside the smartref monorepo the tool carried a second evidence lane alongside the code-fact
workers: it ingested monolithic Markdown reference documents (`docs/library_ref/*.md`, up to
1.4 MB each), read a reviewed content tree (`docs/library_ref/agent_reference/` with
`document_notes.yaml`, `decisions.yaml`, `PRINCIPLES.yaml`), anchored library versions
against the monorepo's own `Cargo.toml`/`uv.lock`, rendered guides and wrote them back into
smartref's `.claude/skills/` and `.codex/skills/`. None of it was reachable from the CLI;
only tests and a `doit` build system drove it.

The operator's direction for the standalone repository is to stop referring back to
monolithic library documents: documentation questions go to the Context7 MCP tools, exact
facts to rustdoc JSON, `cargo metadata`, Griffe and the workers.

## Decision

Delete the lane rather than quarantine it. Removed from `src/library_deep_enrichment/`:
`content`, `docmap`, `render/*`, `principles`, `decisions`, `derivation`, `stages/*`,
`build_system`, `packets`, `manifest`, `retrieve/index_build`, `adapters/docs/behaviors`,
`divergence`, `inventory`, `nominations`, `impact`, `evaluation`, `fact_queries`,
`qualitative`, the dead `intelligence_cli`, the `markdown` intake adapter, the stack and
library manifests under `assets/manifests/`, the `review-packet` template, and
`pilot/documents.yaml`. Dependencies `doit` and (from the original list) `torch` were dropped.

Kept, because surviving code-fact modules import them: `knowledge` (the shared v2 knowledge
model), `evidence_graph`, `revalidation`, `linking`, `authoring`, `qualification`, `scope`,
`generations`, `examples`, `example_discovery`, `reader`, `source_maps`, `migrations`, and
`adapters/docs/markdown_sections` (a byte-precise structural indexer for Markdown that
appears inside source snapshots; the source-facts worker treats Markdown as source, not as a
reference document). `adapters/docs/structured` stays: Sphinx `objects.inv` inventories are
structured API indexes.

Tests deleted with the lane (69 test functions across eight files plus one function in
`test_reuse_contract.py` that read a deleted stage): `test_derivation` (11),
`test_document_and_qualitative_tools` (3), `test_evidence_derivation` (11),
`test_extraction` (5), `test_guide_content` (10), `test_knowledge_v2` (13, its `_sample`
helper moved to `tests/support/knowledge.py`), `test_pilot_skill_blocks` (8),
`test_stage_graph` (7).

On-disk schema markers (`library-guides.*.v1`, `SCHEMA_REVISION`, the
`library_guides_public_api` wire key) keep their historical spelling: the 81 GB of admitted
corpora under `~/.cache/library-deep-enrichment` are written in those formats.

## Evidence

- Import reachability from `cli.py`, `__main__.py` and `_worker_entry.py`, then a fixed-point
  over "is any surviving module or pilot script importing this" (session script, 2026-09-13).
- Baseline in the monorepo checkout, 2026-09-13: `pytest -m "not native_lanes"` → 357 passed,
  76 failed (every failure `ModuleNotFoundError: lance`, the old venv lacked `pylance`).
- After removal with the environment synced from the lockfile and all four workers built:
  `pytest -m "not native_lanes"` → 306 passed; `pytest -m native_lanes` → 22 passed.
  357 + 76 − 69 − 1 = 363 expected versus 328 observed: the remaining 35 were tests in the
  deleted files that the baseline counted as failed (lance) and are now gone with their
  files. No surviving test was removed or skipped.
- `library-deep-enrichment status` against the moved corpus returns family counts identical
  to the pre-move baseline (`entities` 70261, `native_facts` 672073).

## Consequences

- The package no longer knows about any document outside a source snapshot. A future
  "documentation" evidence lane, if wanted, is a registry adapter over the Context7 HTTP API
  with provenance, not a Markdown ingester.
- Four smartref skills (`datafusion-arrow-rust-guide`, `datafusion-pyarrow-guide`,
  `lancedb-ref`, `rust-api-extraction-ref`) still reference `tooling/library_guides/...`
  paths; they were generated by the deleted lane and stay in smartref untouched.
- The recovery path for the deleted code is the first commit of this repository
  (`48bf4ff`, verbatim import) and the untracked original under
  `/home/paul/smartref/tooling/library_guides`, which this migration did not delete.
